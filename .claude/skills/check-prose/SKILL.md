# Check Prose in the Manuscript

检查 `books/ann4us/` 下的正文（去掉公式、代码块、图片、表格之后的叙述文字）和玩具代码是否符合本书的规范。
与 `check-formulas` 互补：那个技能只管 LaTeX 公式的渲染格式，这个技能管中文正文和示例代码。

## When This Skill Applies

- User asks to check / audit the body text of a chapter or the whole book（“检查正文”“看看行文有没有问题”）
- User reports a wording, punctuation, or terminology problem in the manuscript
- User asks to check the toy examples（“检查玩具代码”“toy 代码规范”）
- After writing or heavily editing a chapter, before committing

## Scope

**整个仓库通用** —— 两本书（`books/ann4us/`、`books/toyllm/`）和笔记（`notes/`）共用同一套行文规范。
规则按**文件类型**分派，不看路径，所以直接把仓库根目录传进去就行。

**正文** —— 任何 `*.md`。生成文件 `Book.md` 默认跳过（改正文要改 `chapters/`，改完重跑 `merge.py`）。
正文规则生效时，脚本会自动屏蔽以下区域：

- 围栏代码块（``` ... ```）
- 块级公式（`$$ ... $$`）
- 行内公式（`$...$`）
- 图片 / 链接的 URL 部分
- HTML 标签行（如 `<div style="page-break-after: always;"></div>`）
- YAML frontmatter

**玩具代码** —— 任何 `toy_*.py`。示例代码分两类（见 ann4us 前言）：一类是帮助理解概念的
“玩具代码”，文件名以 `toy_` 开头；另一类是可实际运行的 PyTorch 示例（`perceptron.py`、
`char_rnn.py` 等）。**只有 `toy_` 开头的文件受本技能约束**。目前只有 `books/ann4us/code/`
下有这类文件，但判定靠文件名，新增区域无需改代码。`.venv` 等点开头的目录一律跳过。

### 按区域豁免规则

各区域的例外集中写在仓库根的 `.claude/lint-scope.json`，两个 lint 技能共用：

```json
{
  "exclude": ["CLAUDE.md", "**/CLAUDE.md", "**/todo.md", "node_modules/**", "docs/**"],
  "scopes": [
    {"path": "notes/**", "disable": ["符号记法"]}
  ]
}
```

- `exclude` 里的文件完全不检查（CLAUDE.md 是给 agent 看的说明，里面会引用反例；`node_modules/` 是依赖，`docs/` 是 VitePress 生成的站点，都不是书稿来源）。
- `scopes` 里每条匹配到的 `disable` 取并集。笔记贴合各自论文的记法（`\boldsymbol`、粗体大写矩阵），
  与书稿的记号约定不同且是作者刻意保留的，所以对 `notes/**` 关掉 `符号记法`。
- 被豁免的条数会在结尾如实报出（「另有 N 处被 .claude/lint-scope.json 豁免」），不会悄悄吞掉。
- 加 `--all-rules` 可临时忽略整个配置。

新增一本书或一个笔记目录时，**改这个 JSON 即可，不用动脚本**。

## Steps

检查和修复均有对应脚本，位于 `scripts/` 目录，可传入文件、目录或多个路径：

```bash
# 全仓库（两本书 + 笔记），各区域按自己的标准
python3 scripts/check.py .

# 单个章节 / 单个玩具代码文件
python3 scripts/check.py books/ann4us/chapters/03_ch01_neuron.md
python3 scripts/check.py books/ann4us/code/ch05/toy_rnn.py

# 某一本书 / 只看玩具代码
python3 scripts/check.py books/toyllm/
python3 scripts/check.py books/ann4us/code/

# 忽略区域豁免，全部规则都查
python3 scripts/check.py --all-rules notes/

# 自动修复（覆盖原文件），仅修复标记为可自动修复的规则；先用 --dry-run 看 diff
python3 scripts/fix.py --dry-run books/
python3 scripts/fix.py books/
```

**`fix.py` 同样尊重区域豁免**：对 `notes/**` 不会做符号记法改写。

如果需要人工处理，按以下步骤：

1. Read the target markdown file
2. 剥离公式 / 代码 / 图片链接等非正文区域（见 Scope）
3. 逐条对照下方 Rules 检查剩余正文
4. 报告违规，格式见 Output Format

### 符号记法统一（notation）

全书符号排版必须统一，三条互斥的约定：

1. **标量**：小写字母，如 $x$ 、 $w$ 、 $b$ 、 $\eta$
2. **向量**：粗体小写字母，如 $\mathbf{x}$ 、 $\mathbf{h}$ 、 $\mathbf{b}$
3. **矩阵**：大写字母，如 $W$ 、 $Q$ 、 $K$ 、 $V$

推论（检查时按这几条判断）：

- 粗体只用于向量，因此**不允许粗体大写**（ `\mathbf{W}` 、 `\boldsymbol{X}` ）——矩阵一律用非粗体大写
- 向量不用箭头，因此**不允许 `\vec{}`**
- 大写字母只表示矩阵，因此正文里若某个大写字母指的是向量，要改成粗体小写
- 小写字母若不加粗，就是标量；某个不加粗小写字母指的是向量，要补 `\mathbf{}`
- 粗体统一用 `\mathbf{}`，不混用 `\boldsymbol{}`（希腊字母例外，`\mathbf` 对希腊字母无效，用 `\boldsymbol{}`）

**违规示例：**
```
输入向量 $X = (x_1, x_2, \dots, x_n)$ 与权重矩阵 $\mathbf{W}$ 相乘，
得到 $\vec{y} = \mathbf{W} X$ 。
```

**正确示例：**
```
输入向量 $\mathbf{x} = (x_1, x_2, \dots, x_n)$ 与权重矩阵 $W$ 相乘，
得到 $\mathbf{y} = W \mathbf{x}$ 。
```

检测方法：分两层。

**机械层**（`scripts/check.py` 的 `rule_notation`，扫描所有行内和块级公式内容）：

| 模式 | 判定 |
|---|---|
| `\mathbf{X}` / `\boldsymbol{X}`（首字母大写拉丁字母） | 粗体大写 → 违规，应为非粗体大写 |
| `\vec{...}` | 箭头向量 → 违规，应为 `\mathbf{}` |
| `\boldsymbol{x}`（拉丁字母） | 应统一为 `\mathbf{}` |

对应正则：

```python
BOLD_UPPER = re.compile(r'\\(?:mathbf|boldsymbol|bm)\{\s*([A-Z])')
VEC        = re.compile(r'\\vec\{')
BOLDSYM_LATIN = re.compile(r'\\boldsymbol\{\s*([a-zA-Z])\s*\}')
```

**语义层**（脚本查不出，需要人工／模型逐章判读）：一个不加粗的大写字母到底是矩阵还是向量，
一个不加粗的小写字母到底是标量还是向量，只能结合上下文判断。审阅一章时：

1. 先跑机械层，清掉粗体大写和 `\vec`
2. 通读该章公式，列出出现的所有符号，逐个标注它是标量／向量／矩阵
3. 对照上面三条约定，找出排版与语义不符的符号
4. 同一符号在全书中语义要一致——跨章改名或改排版时，用 `grep -n '符号' books/ann4us/chapters/*.md` 全局确认

是否可自动修复：部分。`\vec{x}` → `\mathbf{x}`（小写）、`\boldsymbol{x}` → `\mathbf{x}`（拉丁小写）
可以自动改；粗体大写改成什么（去掉粗体，还是改成粗体小写）取决于该符号是矩阵还是向量，只报告不自动改。

### 尽量不用破折号（em-dash）

正文里尽量不用破折号（`——`）。破折号密集是**典型的 AI 文风**，读起来一眼就能看出不是人写的。
本书是手写的书，这一点尤其要守住。

破折号在中文里本身是合法标点，所以这条规则是「尽量不用」而非「禁用」：偶尔一处、
确实是最自然的写法时可以留。但只要一段里出现两次，或者整章出现好几次，就该改。

**违规示例：**
```
但即便是这类手写实现，输入输出用的依然是 NumPy 数组——因为 NumPy 数组本身就可以逐元素遍历。
```

**改法**：先看破折号在这里承担什么语义，再选对应的标点。常见四种：

| 破折号的作用 | 改法 | 示例 |
|---|---|---|
| 补充说明原因 | 改逗号，或用「因为…」直接连接 | `……依然是 NumPy 数组，因为它本身就可以逐元素遍历。` |
| 引出解释或列举 | 改冒号 | `核心概念只有一个：门（Gate）。` |
| 插入次要信息 | 改括号 | `参数数量（约七千个）已经无法手动设置。` |
| 话锋一转 / 追加一层意思 | 断成两句 | `……只是形状不同。元素和顺序完全一样。` |

检测方法：在屏蔽掉代码块、公式、URL 之后的正文里查找 `—`（U+2014，一个或多个）。
连字符 `-` 和减号不在此列。

```bash
grep -n '—' <file>
```

是否可自动修复：**否，只报告。** 破折号承担的语义每处不同（补充说明、话锋一转、举例、
同位语），换成哪个标点取决于上下文，机械替换会写坏句子。改写时逐处判断。

> **注意（当前状态）**：全书 14 处，分布在前言（3）、ch00（4）、ch02（1）、ch04（3）、
> ch05（2）、ch07（1）。其中 **ch00 那 4 处全部是本轮 AI 改写时引入的**：该章在本轮
> 工作之前是 0 处；ch07 那处也出自 AI 起草的段落。ch04 的两处属于作者自己写的历史叙述。
> 这条规则的由来正是作者发现改写后的段落 AI 味变浓。

### 公式用 $，代码用反引号（math-vs-code）

正文里区分两类东西，写法不能混：

- **数学的**（变量、参数、符号、算式）→ 行内公式 `$...$`
- **代码的**（标识符、类型、属性、运算符、库函数）→ 反引号

| 类别 | 写法 | 例子 |
|---|---|---|
| 数学变量、参数 | `$w$`、`$b$`、`$x_1$` | 「上图里的 $w$ 是什么呢」 |
| 希腊字母 | `$\sigma$`（**用 LaTeX 命令，不要直接敲 σ**） | 「用 $\sigma$ 表示激活函数」 |
| 算式、取值 | `$w=2$`、`$(784+1) \times 10$` | 「当 $w=2$ 时」 |
| 张量记法 | `$[X]$`、`$[K]$` | 与第零章声明的记法一致 |
| 代码标识符 | `` `np.array` ``、`` `float` ``、`` `new_fc_layer` `` | |
| 属性、运算符 | `` `shape` ``、`` `T` ``、`` `@` `` | `.T` 是 numpy 属性，不是转置符号 $T$ |
| 命名约定前缀 | `` `vec` ``、`` `mat` `` | 讲的是变量名，不是数学符号 |
| **被当作字面量讨论的字符** | `` `a` ``、`` `b` ``、`` `z` `` | 见下方「易错」 |

**易错：单个拉丁字母不一定是数学符号。** 第五章讲 one-hot 时有这样的句子：

> 在这种表示下，`a` 和 `b` 的“距离”为 1，而 `a` 和 `z` 的“距离”为 25。

这里的 `a`、`b`、`z` 指的是**字母本身**，不是数学变量，必须保留反引号。全书这类
共 13 处，全在第五章。**做批量替换时这是最大的坑**：一个「单字母套反引号就转成
$...$」的正则会把这 13 处全改错，而且改完读起来还挺顺，很难发现。

检测方法：机械层只查三类高置信度的：

| 模式 | 判定 |
|---|---|
| 反引号里含希腊字母，如 `` `σ` `` | 违规：应为 `$\sigma$` |
| 反引号里含 `×`，如 `` `(784+1)×10` `` | 违规：算式应写成 `$...$` |
| 屏蔽公式和行内代码后，正文里仍出现裸希腊字母 | 违规：应放进 `$...$` 并用 LaTeX 命令 |

**单字母拉丁的情况不做机械检查**，因为上面那 13 处正当用法会被误报，噪音大于价值。
这一类归语义层：改动涉及单字母反引号时，逐处判断它指的是「变量」还是「字母本身」。

是否可自动修复：否，只报告。转换需要逐符号判断类别。

**批量转换的实操要点**（上次全书迁移的经验）：

1. 先**按章枚举**所有反引号内容再动手，不要全局正则。各章情况差别很大：
   第零章只有 `f` 要转，第五章一个都不能转。
2. 转换只作用于**围栏代码块之外**。
3. 转完不必手工补空格：跑一遍 `check-formulas` 的 `fix.py`，它会把
   `参数$w$代表` 自动补成 `参数 $w$ 代表`。
4. 转完核对**章节代码块与 `toy_*.py` 仍然逐行一致**，确认没有误伤代码块。

### 玩具代码规范（toy-code）

`books/ann4us/code/chNN/toy_*.py` 里的玩具代码，统一遵守三条：

1. **统一使用 numpy 的 array** 表示向量和矩阵，不用 Python 原生列表（`list[float]`、嵌套列表）
2. **向量**的变量名统一以 `vec` 开头
3. **矩阵**的变量名统一以 `mat` 开头

标量不受 2、3 约束，保持普通命名（如 `b`、`lr`、维度 `n`）。命名用蛇形小写，
即 `vec_x`、`mat_w_xh`；允许下划线前缀表示内部临时量（`_vec_h`）。

#### 手写实现：仍然用 numpy 数组

有些代码的目的恰恰是把某个运算一步一步算给读者看——第一章手写向量点积、第三章手写
Softmax、第四章手写卷积加权求和、第五章手写归一化和按概率采样。这类代码要保留摊开的
循环，但**不需要**为此退回 Python 原生列表：numpy 数组本身可迭代、支持 `[i]` 和
`[i][j]` 取值，所以 `zip`、`enumerate`、嵌套下标循环全都照原样工作，循环体一行都不用改。
于是这三条规则对全部玩具代码无条件适用，没有例外。

改写这类函数时有两个实测过的坑：

1. **返回值要包一层 `np.array(...)`。** 列表推导式的结果仍是 `list`，元素变成
   `np.float64`，`print` 出来是 `[np.float64(0.659...), ...]` —— 手稿里注释标的期望
   输出会跟着变成这副样子。包一层就恢复成 `[0.659 0.242 0.0986]`。注意这仍然会改变
   打印格式（数组的 repr 不同于列表），注释里的期望值需要重新跑一遍对齐。
2. **溢出行为不同。** `math.e ** v` 作用在 Python float 上，v 过大时抛
   `OverflowError`；作用在 `np.float64` 上则返回 `inf` 并给一个 RuntimeWarning。
   对 Softmax 这种要取指数的函数，失败方式从报错变成了静默出 `inf`。

在这类函数上方用注释注明 numpy 的现成写法，让读者对照“摊开的过程”和“实际该用的一行”。
注释要写准，不要臆造不存在的 API：

| 手写函数 | numpy 现成写法 |
|---|---|
| 点积 | `vec_a @ vec_b`，或 `np.dot(vec_a, vec_b)` |
| 加权求和 | `np.sum(mat_x * mat_w)` |
| 归一化 | `vec_x / vec_x.sum()` |
| 按概率采样 | `np.random.choice(len(vec_probs), p=vec_probs)` |
| Softmax | **numpy 没有** `softmax`。只能说 `np.exp` 可整体求指数，整个函数可简写成 `np.exp(vec_z) / np.exp(vec_z).sum()` |

> 脚本仍支持一个 `toy-exempt` 逃生口（`.py` 里写普通注释、章节 md 里写 HTML 注释放在
> 代码块上方，脚本向上回看 3 行），用于将来确实无法用 numpy 表达的代码。它只豁免第 1 条，
> 不豁免命名。**目前全书没有任何代码使用它。**

**违规示例：**
```python
from math import e

def dot_product(a: list[float], b: list[float]) -> float:
    return sum(x * y for x, y in zip(a, b))

w = np.array([[0.11, 0.12], [0.21, 0.22]])
x = np.array([0.4, 0.5])
```

**正确示例：**
```python
import numpy as np

mat_w = np.array([[0.11, 0.12], [0.21, 0.22]])
vec_x = np.array([0.4, 0.5])
vec_y = mat_w @ vec_x
```

检测方法：分两层。

**机械层**（`scripts/check.py` 的 `rule_toy_numpy` 和 `rule_toy_naming`）：

| 检查 | 判定 |
|---|---|
| 出现 `list[float]` / `list[list[float]]` 标注 | 违规：改用 numpy array（可被 `toy-exempt` 豁免） |
| 赋值右侧是纯数字的列表字面量（如 `[1, 2, 3]`、`[[1, 2], [3, 4]]`） | 违规：改用 numpy array（可被 `toy-exempt` 豁免） |
| 赋值右侧构造出**二维**数组，左侧名不以 `mat` 开头 | 违规（不可豁免） |
| 赋值右侧构造出**一维**数组，左侧名不以 `vec` 开头 | 违规（不可豁免） |

注意这里**没有**「文件里没出现过 `np.` 就报违规」这一条。那个判据太粗：
`toy_neuron1.py` 只有 `w * x` 这样的标量运算，`toy_lstm.py` 只做函数组合，
两者都没有任何向量或矩阵，本就不该 import numpy。规则只在代码**真的用列表表示了
向量或矩阵**时才报——即出现列表类型标注，或出现纯数字的列表字面量。

判定维度靠 numpy 构造调用本身，这是这条规则能机械检查的关键：

- 矩阵：`np.array([[...]])`、`np.zeros((n, m))`、`np.random.rand(n, m)`、`x.reshape(n, m)`
- 向量：`np.array([...])`（非嵌套）、`np.zeros(n)`、`np.random.rand(n)`

正则**锚定在右侧表达式开头**，要求这个赋值本身就是数组，而不是碰巧提到了数组。
否则 `layer = new_fc_layer(np.random.randn(100, 300), ...)`（绑定的是闭包）和
`kernels = [(np.array([[..]]), b), ...]`（绑定的是元组列表）都会被误判成矩阵。
形状判不出来时返回 `None`、不报，宁可漏报也不误报。

**语义层**（脚本查不出，需要人工／模型判读）：

1. 右侧不是 numpy 直接构造的变量（函数返回值、切片、运算结果），机械层不判定维度，要人工确认
2. 元素是数组的容器（如 `kernel_list`）该怎么命名，规则没有规定，需要单独约定
3. 改名要同步所有引用点，包括函数形参、闭包捕获的变量、注释和 print 里的字符串
4. **章节里的代码块要和 `toy_*.py` 保持一致**：同一段玩具代码在 `books/ann4us/chapters/*.md` 里
   以 ```` ```python ```` 代码块重复出现，改完 `.py` 必须同步改章节，否则书里印的和仓库里的不一样

第 4 点没有做成机械检查，因为章节代码块无法可靠地区分“玩具代码”和 PyTorch 示例，
且第零章的 NumPy 入门小节用 `a`、`b` 这类名字演示通用 numpy 用法，纳入检查会大量误报。

是否可自动修复：否。改用 numpy 是重写而非替换；改名需要同步全部引用点，
机械替换容易改错闭包捕获和字符串。两者都只报告。
