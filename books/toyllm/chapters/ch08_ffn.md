红箭头指着 FFN+Residual，Decoder Block 里的第二个子层。

和注意力正好相反：**FFN 是严格逐 token 的**。每个位置各算各的，互不相干。如果说注意力负责"从上下文里收集信息"，FFN 就负责"消化这些信息"。

要讲的几点：

- **SwiGLU 用三个矩阵，不是普通 FFN 的两个**。`gate_proj` 和 `up_proj` 把 576 维升到 1536 维，其中 gate 那一路过一遍 SiLU 激活函数，两路相乘之后再由 `down_proj` 降回 576 维。

- **参数大头在这里**。一个 block 里 FFN 占 2,654,208 个参数，占该 block 的 75%；30 层加起来占全模型的 59%。



## FFN

### 和注意力的分工

FFN 和注意力正好相反：**它严格逐 token**。每个位置各算各的，第 3 个 token 的 FFN 完全不知道第 1、2 个 token 的存在。

一个常见的说法是：

- **注意力负责"从上下文里收集信息"**——横向，跨位置
- **FFN 负责"消化这些信息"**——纵向，在单个位置内部做变换

一个 Block 就是"先收集、再消化"，重复 30 次。

### 最朴素的形式

2017 年原始论文里的 FFN 只有两个矩阵：

$$\mathrm{FFN}(\mathbf{x}) = W_2 \cdot \mathrm{ReLU}(W_1 \mathbf{x})$$

先把 576 维升到一个更宽的中间层（通常是 4 倍，2304），过一个激活函数，再降回 576 维。

两个"为什么"要讲清楚：

**为什么要先升维再降维？** 升维给非线性变换更大的施展空间。可以类比成：想在低维空间里把纠缠的东西分开很难，升到高维就容易了，分开之后再压回来。

**为什么必须有激活函数？** 没有它，`W₂ · W₁ · x` 还是一个线性变换，两层等于一层，30 层也等于一层。**非线性是深度网络之所以"深"有意义的唯一理由**——这句话值得写重一点，因为很多读者对激活函数只知其名。

### 它是参数大头

一个 block 里 FFN 占 2,654,208 个参数，占该 block 的 **75%**；30 层加起来占全模型的 **59%**。第二章 `layer.png` 上右边三块的总宽度是左边四块的三倍，一眼就能看出来。

如果想多说一句机理：有一种流行的解释把 FFN 看成一个**键值记忆库**——`up_proj` 的每一行是一个"模式"（key），输入和它匹配得越好、激活值越大；`down_proj` 的对应列则是"取出的内容"（value）。这个视角能解释为什么模型的事实性知识主要存在 FFN 里。但它只是一种解释，别讲得太满。



## SwiGLU

### 门控的思路

现代模型不用 ReLU-FFN 了，改用 GLU（Gated Linear Unit）家族。

GLU 的想法是**门控**：不再是"投影完过一个激活函数"，而是并行做两条投影，一条当"门"，一条当"内容"，然后逐元素相乘。

$$\mathrm{GLU}(\mathbf{x}) = \sigma(W_1\mathbf{x}) \odot (W_2\mathbf{x})$$

门那一路经过激活函数后取值在 0 到 1 之间，相当于给内容那一路的每个维度都配了一个开关——**哪些信息放过去，是由数据自己决定的**。这比"一刀切"的 ReLU 灵活。

### SwiGLU

把门那一路的激活函数换成 SiLU（也叫 Swish），就是 SwiGLU：

$$\mathrm{SiLU}(x) = x \cdot \sigma(x), \qquad \mathrm{SwiGLU}(\mathbf{x}) = \mathrm{SiLU}(\mathrm{gate}(\mathbf{x})) \odot \mathrm{up}(\mathbf{x})$$

SiLU 和 ReLU 相比：曲线处处光滑，没有 ReLU 在 0 处那个折角；负值区不是硬性归零，而是有一个浅浅的凹陷，小的负值还能透过去一点。

完整的 FFN 因此是三个矩阵：

$$\mathrm{FFN}(\mathbf{x}) = \mathrm{down}\big(\, \mathrm{SiLU}(\mathrm{gate}(\mathbf{x})) \odot \mathrm{up}(\mathbf{x}) \,\big)$$

正好对应第二章看到的 `gate_proj` / `up_proj` / `down_proj`。

### 1536 是怎么来的

第二章埋的问题，在这里回答。

SwiGLU 要三个矩阵，比普通 FFN 多一个。如果中间层还是 4 倍宽，参数就要多 50%。想维持同样的预算：

```
普通 FFN：2 个矩阵 × 576 × 2304  = 2,654,208
SwiGLU ：3 个矩阵 × 576 × h      = 2,654,208
                    →  h = 2/3 × 2304 = 8/3 × 576 = 1536
```

**分毫不差。** 这就是为什么各家模型的 `intermediate_size` 都是隐层维度的 8/3 倍左右——不是什么玄学，是"换个结构但别涨参数"算出来的。

### 一句诚实的话

SwiGLU 为什么比 ReLU 好？提出它的论文（*GLU Variants Improve Transformer*）在结论里写的是：我们没有解释，只能归功于"神的恩典"（divine benevolence）。

**它能工作，但机理不明。** 这句话正好合本书的定位——讲 how，不讲 why。深度学习里这样的东西不少，如实说明比强行编一个理由好。



## 代码实现

三个 `nn.Linear`（`bias=False`），forward 一行。

对拍：与 `LlamaMLP` **逐位相同**。注意这一章的部件本身还能做到 bit-identical——因为它不经过 RoPE，没有那 1 ulp 的余弦误差。上一章说"从此改用相对误差"，指的是**整条链路**；单个部件能严格比就严格比。

填进骨架的第二个空位，Block 至此完整：

```
h = x + Attn(norm₁(x))
y = h + FFN(norm₂(h))
```

### 四级验收

按严格程度递进，一级一级过：

**一、参数量 == 134,515,008。** 一个不多一个不少。漏接一个张量、多建一组 bias，在这里立刻暴露。这是最便宜的检查，先做。

**二、31 层 hidden states 逐层比对**，相对误差都在 1e-6 以内。

为什么要逐层比而不是只比最后一层？因为**只比最后一层，定位不了问题**。逐层比能一眼看出误差是从第几层开始炸的，那一层就是 bug 所在。

这里有个 HF 的索引约定必须讲清楚，否则一定踩坑：

| 索引 | 内容 |
|---|---|
| `[0]` | embedding 的输出 |
| `[1] .. [29]` | 第 i 个 block 的**输入**（也就是第 i-1 个 block 的输出） |
| `[30]` | 最后一个 block 的输出，**并且已经过了 final norm** |

最后一个是特例。拿它和 block 29 的裸输出去比，会看到 27 倍的差距——那个数字毫无意义，纯粹是没过 norm 造成的。

**三、logits 的 argmax 完全一致。** 数值有微小误差没关系，但选出来的词必须一模一样。

**四、greedy 解码 20 个 token，和第一章那句话一字不差。** 这是终极判据：解码是一连串 argmax 决策，任何一步选错，后面整段都会跑偏。能逐字节对上，说明整条链路真的通了。
