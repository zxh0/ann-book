> **本章代码**：只用 `embed_tokens` 一个矩阵，把它**读两遍**——正着读是查表（入口），倒着读是投影（出口）。

注意这张图上有**两个**红箭头：一个在最左边的 Embedding Layer，一个在最右边的 Linear Projection。一头一尾，隔着 30 层。

把它们放进同一章，是因为**它们是同一个矩阵**。

上一章我们把文字变成了 `9 5 2` 这样的整数。整数还不能算——模型要的是向量。这一章就做这件事，顺便把反方向也做了。

SmolLM2 的 `tie_word_embeddings` 为 `true`，入口的查表矩阵和出口的投影矩阵共用一份权重。所以第二章打开权重文件时会发现一件怪事：里面根本没有 `lm_head.weight`——答案就在这里。

同一个矩阵，两个方向：

- **方向一（入口）**：token id 进，向量出。`9 5 2` → `(3, 576)`。本质是按行号取行。
- **方向二（出口）**：向量进，分数出。`(576,)` → `(49152,)`。本质是和词表里每一行做点积，谁像谁得分高。

这个矩阵是 49152 × 576 = **28,311,552** 个参数，一个人占了全模型的 21%。共享省下的正是这 21%。



## 词嵌入



### 一张表

`embed_tokens` 是一张 **49152 行 × 576 列**的表，一行对应一个 token。

查表就是取第 i 行：token 9 的向量就是 `W[9]`。没有比这更简单的操作了——它甚至不是矩阵乘法，只是一次索引。

不过换个角度看，它**也是**矩阵乘法：一个 one-hot 向量 $\mathbf{e}_i$ 乘以 $W$ ，结果正好是第 i 行。这个等价关系值得点破，它解释了为什么"查表"这种离散操作能出现在一个全是连续运算的网络里——它本来就是矩阵乘法，只是恰好可以用索引抄近路。



### 这 576 个数是什么

不是人设计的，是训练出来的。576 个维度没有一个有名字，也没有一个能单独解释。所谓"语义"，是整个向量在这个 576 维空间里的位置。

这里值得和 word2vec 对照一下（`../ai_book` 第六章讲过）。思路是同源的：都是把词映射成稠密向量，都指望"意思相近的词位置相近"。

但要说清楚一件事：**LLM 的词嵌入不是 word2vec。** word2vec 的训练目标就是让相似的词靠近，所以它的向量空间干净、余弦相似度好用、`king - man + woman` 能算出来。而 `embed_tokens` 是为整个模型服务的，还要兼职做输出投影（见下一节），语义结构会糊得多。等会儿的实验会让读者亲眼看到这一点。



### 尺寸

```
49152 × 576 = 28,311,552
```

占全模型的 21%。第二章 `weights.png` 上那块绿色就是它。

一个实现细节：Llama 系模型**不做 embedding scaling**。有些模型（比如原始 Transformer）会把查出来的向量乘以 $\sqrt{d}$ ，这里没有，查出来直接用。



## 投影



### 出口需要什么

模型算到最后，手里是一个 576 维的向量，要变成 49152 个词各自的分数。这需要一个 49152 × 576 的矩阵。

而这个形状，和词嵌入表**一模一样**。



### 权重共享

`config.json` 里 `tie_word_embeddings: true`——直接复用，不再单独存一份。这就是第二章那个谜底：文件里为什么没有 `lm_head.weight`。

计算上就是 `x @ W.T`，结果的第 j 个分量是：

$$\mathrm{logits}_j = \mathbf{x} \cdot \mathbf{w}_j$$

也就是 $\mathbf{x}$ 和词表第 j 行的点积。

**语义上，出口做的事情是「在词表里找最像的」。** 谁和当前这个向量方向一致、模长又大，谁的分数就高。



### 为什么能共享

入口把"词"翻译成"向量"，出口把"向量"翻译回"词"。本来就是同一本词典的两种查法——一个从词条查释义，一个从释义找词条。共享权重不是省钱的技巧，是这件事的本来面目。

省下的正是那 21%。对 135M 这种小模型是笔大买卖；模型越大，词嵌入占比越小（同样一张表在 SmolLM2-1.7B 里只占 5.9%），共享的收益也越小。SmolLM2 三个尺寸都做了共享，但更大的模型往往就不做了——Qwen2.5-7B、Mistral-7B、OLMo-2-7B 都是各存一份。



### logits 不是概率

它可正可负，量级也没有约束。要变成概率得过 softmax，那是第十章的事。这一章拿到 logits 就够了——排序不受 softmax 影响，想知道"模型觉得下一个词是什么"，直接看 argmax 就行。



## 代码实现

一个类，一个矩阵，两个方法。**绝不存两份权重**——那样既浪费 28M，又会在改动时出现两份不一致。

```
encode:  (T,)        --索引-->  (T, 576)
decode:  (..., 576)  --@ W.T-->  (..., 49152)
```

对拍：方向一和 HF 的 `model.model.embed_tokens` 比，方向二和 `model.lm_head` 比，都应该**逐位相同**。这一步还没有任何浮点误差累积，能对上就是能对上。



### 回环实验

把一个 token embed 出来，再原样投回去，看 top-10 是哪些词。

按直觉，argmax 应该就是它自己——因为 $\mathbf{e}_i \cdot \mathbf{e}_i = \|\mathbf{e}_i\|^2$ ，自己和自己最像。

但**不保证**。因为分数是点积，同时受夹角和模长影响：某个模长特别大的词，即使方向差一点，也可能挤到前面去。

这个小实验有两个收获：

1. **点积不等于相似度**。要衡量"像不像"该用余弦，而点积把模长也算了进去。这直接引出下一章——真实模型在 `lm_head` 之前有一个 RMSNorm，管的就是模长。
2. **top-10 里大概率不是近义词**，而是同一个词的大小写变体、带空格变体、复数形式。这个结果可能让人失望，但它诚实地说明了上面那句话：LLM 的词嵌入不是 word2vec。这个观察本身就值得写进书里，比硬凑一个漂亮的类比强。



### 零层的 LLM

把两个方向直接接起来：

```
ids → embed → lm_head → logits
```

跑一句话，看它预测的下一个词。输出**必然是胡言乱语**——中间 30 层一层都没有，模型不知道上下文，甚至不知道词序，它只是在问"和当前这个词最像的词是哪个"。

这是全书最重要的反面教材。读者看到这个结果，才会真正明白第五到第九章在补什么：**中间那 30 层不生产词向量，它们加工词向量。**



## 本章小节

这一章造了模型的第一层和最后一层，用的是同一个矩阵：

- **方向一**：token id → 576 维向量，按行取表
- **方向二**：576 维向量 → 49152 个分数，和每一行做点积
- 两者共用一份权重，这就是第二章 `lm_head.weight` 缺席的原因

引擎现在是 `ids → embed → lm_head → logits`——能跑，能吐词，但是个零层模型，说的全是胡话。

还留了个问题：投影会被向量模长带偏。

下一章我们不急着往中间填东西，先把 30 层的**骨架**搭出来——顺便回答上面那个模长问题。
