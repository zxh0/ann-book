# 第二章 · 模型文件与权重

这一章只读，不算，而且只碰 `model.safetensors` 这一个文件。把它拆开，看清那 1.35 亿个
参数以什么形式躺在磁盘上。`config.json` 留到后面真正需要的时候再读。

## 运行

```bash
cd code
./download_model.sh                                 # 还没下权重的话，先跑这个
uv run python book/ch02/load_header.py              # 读 N 和 JSON 头
uv run python book/ch02/load_weights.py             # 按索引把 272 块数据逐块读出来
uv run python book/ch02/load_weights_hf.py          # 同样的事，交给 safetensors 库做
```

## 文件

| 文件 | 作用 |
|---|---|
| `load_header.py` | 只用标准库，解出头部长度 N，打印 JSON 头，报出三段各多少字节 |
| `load_weights.py` | 按 JSON 头里的索引把数据区一块一块读出来，打印每块的名字、offset、长度，验证正好读到文件末尾，再统计参数都花在哪 |
| `load_weights_hf.py` | 同样的清单和统计，改用 safetensors 库，用来和上一个对照 |

## 三段结构

`load_header.py` 的输出：

```
N = 30528
{"__metadata__":{"format":"pt"},"model.embed_tokens.weight":{...}, ...}
头部 8 + 30528 = 30536 字节
数据 269030016 字节
总计 269060552 字节
```

第二行是那 30,528 字节的 JSON 头，原样打印，就是文件里的一整行。想看得清楚：

```bash
uv run python book/ch02/load_header.py | sed -n 2p | python3 -m json.tool
```

## 逐块读出来

`load_weights.py` 把 272 块挨个读一遍，先按层折叠成 32 行看全局：

```
按层折叠：

┌──────────────┬───────────┬───────────┬──────────┐
│ part         │   tensors │    offset │    bytes │
├──────────────┼───────────┼───────────┼──────────┤
│ embed_tokens │         1 │         0 │ 56623104 │
│ layers.0     │         9 │  56623104 │  7080192 │
│ layers.1     │         9 │  63703296 │  7080192 │
│ layers.10    │         9 │  70783488 │  7080192 │
...
│ layers.9     │         9 │ 261948672 │  7080192 │
│ norm         │         1 │ 269028864 │     1152 │
└──────────────┴───────────┴───────────┴──────────┘
```

折叠之后一眼可见的两件事：30 层每层都是 9 个张量、7,080,192 字节，结构完全一致；
而层的物理顺序是**字母序**，`layers.1` 后面紧跟 `layers.10`，`layers.3` 排在 `layers.29`
之后。谁要是按 JSON 里的出现顺序去数第几层，第 2 层会拿到第 11 层的权重，且不报错。

然后是逐个张量的明细，再跟两段小结：

```
逐个张量。名字去掉了 model. 前缀和 .weight 后缀，layers. 缩写成 l.

┌───────────────────────────────┬──────────────┬───────────┬──────────┐
│ tensor                        │        shape │    offset │    bytes │
├───────────────────────────────┼──────────────┼───────────┼──────────┤
│ embed_tokens                  │ (49152, 576) │         0 │ 56623104 │
│ l.0.input_layernorm           │        (576) │  56623104 │     1152 │
...
│ norm                          │        (576) │ 269028864 │     1152 │
└───────────────────────────────┴──────────────┴───────────┴──────────┘

张量   272 块
头部   8 + 30528 = 30536 字节
数据   269030016 字节，读完剩 0 字节
总计   269060552 字节，文件实际 269060552 字节

正好读完，一个字节不多不少。

┌───────────────┬─────────────┬─────────────┬─────────┐
│ part          │       bytes │      params │   ratio │
├───────────────┼─────────────┼─────────────┼─────────┤
│ 词嵌入        │  56,623,104 │  28,311,552 │   21.0% │
│ 30个Decoder块 │ 212,405,760 │ 106,202,880 │   79.0% │
│ 最后的norm    │       1,152 │         576 │    0.0% │
│ 合计          │ 269,030,016 │ 134,515,008 │         │
└───────────────┴─────────────┴─────────────┴─────────┘
```

两项检查：读每块之前确认它的起点紧接着上一块的终点，拦住中间的空隙；读完确认后面
一个字节都不剩，拦住尾部多余。任一不过就退出码 1。少了第一项，中间有空隙而尾部刚好
差同样多的话，总数照样能对上。

统计用的是真实读到的字节数，不是 JSON 里写的数。bf16 每个数 2 字节，所以参数量就是
字节数的一半，合计 134,515,008，和第一章 `transformers` 报的一致。

画表格用的是 `tabulate`，它靠 `wcwidth` 才知道中文占两列，两个包都在 `pyproject.toml`
里，只为打印服务。

## 换成库来做

`load_weights_hf.py` 得到的名字、长度、统计和上面逐个相同，但有一件事它做不到：

**safetensors 的 Python API 不暴露 `data_offsets`。** `keys()` 只给名字，`get_tensor()`
只给张量，每块数据在文件里的位置是看不见的。所以库版本那一列长度是拿形状乘 dtype
**算**出来的，不是从文件里**读**出来的；连带也没法验证“数据区正好读完、中间没有空隙”，
只能用 `文件大小 - 数据总量 = 30536` 倒推出头部有多大。

反过来，形状和 dtype 库给得很痛快，自己拆则要从 JSON 头里取。
