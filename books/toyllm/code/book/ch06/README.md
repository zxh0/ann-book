# 第六章 · 注意力机制（Attention）

第五章搭好了30层的骨架，留了两个空位。这一章填第一个：注意力。它是整个模型里
唯一让词元之间交换信息的部件，词嵌入、RMSNorm、FFN眼里每个位置都是孤立的。
从这一章起，“Once upon a”才第一次真正参与计算。

第二个空位（FFN）从随机数改成了**返回0**，所以引擎里不再有随机数，同样的输入
每次跑出来都一样。

## attn做了什么

`attn(x, layer)`比第五章多了一个参数`layer`，因为注意力要用这一层自己的四个
矩阵：`q_proj`、`k_proj`、`v_proj`、`o_proj`。形状一路是这样变的：

```
x              (T, 576)
q = x @ Wq.T   (T, 576)  → 拆头 → (9, T, 64)
k = x @ Wk.T   (T, 192)  → 拆头 → (3, T, 64) → 每头复制3份 → (9, T, 64)
v = x @ Wv.T   (T, 192)  → 拆头 → (3, T, 64) → 每头复制3份 → (9, T, 64)
scores         (9, T, T)   q和k的点积，除以√64 = 8
掩码            右上角（未来）置成-inf
probs          (9, T, T)   softmax，每行和为1
out            (9, T, 64)  probs @ v
拼头            (T, 576)    9个64维首尾相接
o_proj         (T, 576)    把各头的结果混合起来
```

`head_dim`没有单独的字段，是用576 / 9算出来的。

**GQA的坑。** k和v只有3个头，要复制成9个去对齐q。必须用`repeat_interleave`，
排成`[0,0,0,1,1,1,2,2,2]`，也就是q头0、1、2共用kv头0。写成`repeat(3, 1, 1)`会
排成`[0,1,2,0,1,2,0,1,2]`，形状一模一样，不报错，配对全错。

## 对拍

这一章还对不上`transformers`，因为缺RoPE。改用PyTorch自带的
`F.scaled_dot_product_attention(q, k, v, is_causal=True)`当参照，它正好就是
“没有位置信息的因果注意力”。

注意PyTorch 2.2的这个函数还不支持GQA（`enable_gqa`参数要到2.5才有），所以喂进去
之前得先自己把k、v复制成9个头。这也顺便检验了复制的顺序。

| | 相对误差 |
|---|---|
| 我们的`attn`，第0、15、29层，T取4和37 | 2.8e-8 ~ 8.5e-7 |
| 故意把复制顺序写错（`repeat`） | 0.61 |

对不上的那一点是浮点舍入：PyTorch那个函数内部的累加顺序和我们不一样，所以不是
逐位相同。但正确和错误之间差了六个数量级，没有灰色地带。

（这组数是临时脚本跑出来的，还没放进这个目录。）

## 为什么FFN返回0，而不是返回x

```python
x = x + self.ffn(self.rms_norm(x, layer["post_attn_norm"]))
```

返回0，这一行就是`x = x + 0`，FFN这个子层等于不存在，看到的只有注意力的效果。

返回`x`看着像“什么都不做”，其实不是：`ffn`收到的是**归一化之后**的`x`，原样返回，
每一层都会往主干上再加一份归一化过的`x`。实测第30层后的模长，返回`x`是1414.4，
返回0是1259.3，多出来的就是每层多加的那一份。

## 为什么是ppo，为什么一直重复

一句话：注意力确实起作用了，但没有位置编码、也没有FFN，30层注意力基本是在给
整句话求平均，各位置越来越像，最后整句话收敛成同一个向量。出口挑中`ppo`，是因为
它那一行模长大；一直重复，是因为每多追加一个词元，平均值几乎不动。

### 一、前面的词元确实参与了计算

换几个输入，第一个预测各不相同：

| 输入 | 第一个预测 |
|---|---|
| `Once upon a time` | `ppo` |
| `Hello` | `ocracies` |
| `The cat sat on the` | `typically` |
| `def main():` | `Ġnor` |

预测随上下文变，说明注意力在混合信息，并不是什么输入都塌到`ppo`上。

### 二、但混合得几乎是平均

最后一个位置的注意力权重（9个头取平均），和真模型对比。真模型那一行是借
`transformers`跑的，带RoPE、带FFN：

| | 第15层 | 第29层 |
|---|---|---|
| 我们的引擎 | 0.143, 0.328, 0.227, 0.302 | 0.265, 0.244, 0.244, 0.247 |
| 真模型 | **0.935**, 0.023, 0.020, 0.022 | **0.697**, 0.043, 0.035, 0.225 |

真模型的注意力很集中，第15层有93.5%落在第一个词元上，这个现象叫attention sink。
我们的几乎是均匀的。注意力退化成平均，过完30层，各位置就被抹成了一个样：

| | 4个位置两两的余弦 |
|---|---|
| 词嵌入阶段 | -0.11 ~ 0.32，各不相干 |
| 第30层后 | 0.983 ~ 0.999，几乎是同一个向量 |

所以出口拿到的，是“这句话的平均意思”，不是“最后一个词元在这个上下文里的意思”。

**说明**：注意力变平，现在分不清是缺RoPE还是缺FFN造成的，两样都缺。权重是在有
RoPE的条件下训练出来的，q和k没转过，点积就对不上训练时的样子，这个解释说得通，
但要等第七章补上RoPE才能单独验证。

### 三、为什么是ppo：模长又占了便宜

| 词元 | 分数（点积） | 这一行的模长 |
|---|---:|---:|
| `ppo` | 20.46 | 4.441 |
| `usually` | 17.02 | 2.607 |
| `only` | 16.89 | 3.060 |

按余弦排，第一是`Ġusually`，`ppo`只排第86。它赢在自己那一行模长大，和第四章
`Hello`被`<filename>`抢走是同一件事：点积同时受夹角和模长影响。

### 四、为什么一直重复

和第四章“自己和自己最像”不一样。单独喂一个`ppo`，预测的是`Ġarbitrarily`，不是
`ppo`，所以不是`ppo`会预测出它自己。

原因是平均有惯性。最后一个位置约等于全句的平均，每追加一个`ppo`，出口向量和上一圈
的余弦都在0.9989到0.9997之间，几乎不动，预测也就不变。而且`ppo`越多，平均越偏向
`ppo`。

| 序列长度 | 与上一圈的余弦 | 预测 |
|---|---|---|
| 5 | 0.9989 | `ppo` |
| 6 | 0.9994 | `ppo` |
| 7 | 0.9994 | `ppo` |
| 8 | 0.9996 | `ppo` |
| 9 | 0.9997 | `ppo` |
