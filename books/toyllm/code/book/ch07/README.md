# 第七章 · 位置编码（Positional Encoding）

第六章的注意力分不清词序：它只做加权求和，加法不分先后。这一章补上RoPE，
注意力才算完整。

RoPE不往向量上加东西，而是把q和k按位置转一个角度。它不改变任何形状，也没有
一个可训练参数，全靠`rope_theta`算出来的一张cos/sin表，所以权重文件里找不到它。
它在注意力内部，30层每一层都要转一次。

## 运行

```bash
cd code
./download_model.sh                        # 还没下权重的话，先跑这个
```

## RoPE做了什么

64维看成32个平面，第i维和第i+32维是一对。第m个位置上，第i个平面转
`m * inv_freq[i]`这么大的角度：

```
inv_freq[i] = 1 / 100000 ** (2i / 64)     i = 0 .. 31     (32,)
angles      = 位置 × inv_freq                               (8192, 32)
抄两遍拼起来，第i维和第i+32维转同一个角度                      (8192, 64)
cos, sin                                                    各(8192, 64)
```

表在`Model.__init__`里算一次，30层、每一圈都查同一张。用的时候取前T行：

```
q              (9, T, 64)   → q * cos + rotate_half(q) * sin → (9, T, 64)
k              (3, T, 64)   → k * cos + rotate_half(k) * sin → (3, T, 64)
v              不转
```

k在复制成9个头之前转，只用转3个头。`rotate_half`把`[a | b]`变成`[-b | a]`，
就是二维旋转公式写成整段向量的样子。

**两个坑，都不报错。**

- `rope_theta`是100000，不是常见的10000。必须从config读。
- 配对方式是half-split，`(0,32) (1,33) …`，不是原始论文的相邻配对`(0,1) (2,3) …`。
  config里`rope_interleaved: false`说的就是这个。`rope_table`里加了一行
  `assert`，config要是说相邻配对，直接拦下来。

两种做错的方式都是真旋转，都保模长，下面对拍那张表里能看到它们错多少。

## 打乱实验

上一章说“打乱输入，输出一模一样”，这句话得说准确。有因果掩码，前面的位置
各自能看见的词元不一样，打乱以后它们的输出跟着变，第1层起互相牵连，整条流水线
的结果本来就会变：第六章的引擎打乱“Once upon a”，第一个预测就从`ppo`变成了别的。

真正和顺序无关的，是**第0层注意力在最后一个位置的输出**，前提是最后一个词元不动。
这一行就是对前面所有value的加权求和，权重只看q和k像不像。

`shuffle.py`只打乱前三个词元，把`rope`换成什么都不做，就是上一章的注意力：

```
词元顺序                          没有RoPE      有RoPE
Once upon a time                   0.0e+00     0.0e+00
upon Once a time                   1.5e-08     2.2e-02
a upon Once time                   1.2e-07     4.6e-02
Once a upon time                   1.2e-07     4.1e-02
a Once upon time                   2.4e-07     5.4e-02
```

没有RoPE那一列只剩浮点舍入，加法换了顺序，最后一位会变。有RoPE那一列差在第二位
小数，词序进来了。

## 对拍

终于能和`LlamaAttention`对了。输入是词嵌入过完这一层的`input_norm`，也就是
`attn`真正收到的东西；1000那组是随机挑的ID，只为了够长。

```
    T   层       绝对误差       相对误差       相邻配对  theta=10000
    4   0      0.0e+00      0.0e+00      3.2e-02      1.1e-02
    4  15      0.0e+00      0.0e+00      1.2e-01      1.9e-02
    4  29      0.0e+00      0.0e+00      5.0e-02      1.3e-02
   26   0      0.0e+00      0.0e+00      1.1e-01      4.5e-02
   26  15      0.0e+00      0.0e+00      5.2e-01      1.7e-01
   26  29      0.0e+00      0.0e+00      2.5e-01      1.0e-01
 1000   0      4.8e-07      2.4e-07      1.6e-01      6.3e-02
 1000  15      4.8e-06      1.9e-07      6.7e-01      5.7e-01
 1000  29      6.1e-05      1.6e-07      6.5e-01      1.5e-01

inv_freq和transformers逐位相同   True
cos表前 130行      0个数不同，最大差0.0e+00
cos表前 131行      8个数不同，最大差3.0e-08
cos表前1000行   1028个数不同，最大差1.2e-07
```

短句子逐位相同，长了就不是。我们的cos表启动时一次算8192行，transformers每次现算
T行，角度逐位相同，但`torch.cos`算多大一块，走的不一定是同一段代码，余弦偶尔差
最后一位。实测T不超过130时一位不差，从131起时有时无（T=300又恰好一位不差）。

这一位的差，相对误差一直在1e-7上下，绝对误差却跟着输出的量级走：第29层输出大到
几百，绝对误差就到了6e-5。所以**从这一章起，判据换成相对误差**
`max|diff| / max|ref| < 1e-5`，不用固定的绝对误差。

做错的两种，相对误差在1e-2到1e0之间，和1e-7隔着五个数量级以上，没有灰色地带。
注意它们在T=4时也只有百分之几：位置越靠前，转的角度越小，错的配对方式也错得少。
所以对拍要用长一点的输入。

## 注意力权重表，再打一次

第六章留了个问题：注意力几乎是均匀的，是缺RoPE还是缺FFN造成的？补上RoPE，
把最后一个位置的注意力权重（9个头取平均）再打一次：

| | 第15层 | 第29层 |
|---|---|---|
| 第六章（没有RoPE） | 0.143, 0.328, 0.227, 0.302 | 0.265, 0.244, 0.244, 0.247 |
| 这一章（有RoPE） | 0.226, 0.353, 0.202, 0.220 | 0.307, 0.251, 0.220, 0.222 |
| 真模型 | **0.935**, 0.023, 0.020, 0.022 | **0.697**, 0.043, 0.035, 0.225 |

数变了，但还是几乎均匀，30层后4个位置两两的余弦是0.992 ~ 1.000，比第六章的
0.983 ~ 0.999还要挤。所以注意力变平主要不是缺RoPE造成的，要看第八章填上FFN以后
怎么样。
